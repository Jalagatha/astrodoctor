# Astro-Doctor

Astro-Doctor is a crew wellbeing prototype. An astronaut checks in (mood, sleep, energy, stress, missing home). An **adaptive engine** recommends one of five VR theme worlds for 10–30 minutes. A **re-check** afterwards teaches the engine what works for that person.

```
Check-in → Adaptive engine (phase + mood) → VR session (10–30 min) → Re-check (learns what works)
Theme worlds: Family · Nature · Learning · Active play · NASA calm
```

The engine is a gradient-boosted model trained on a synthetic dataset, plus a per-astronaut Thompson-sampling layer that learns from each re-check. The dataset, model, evaluation and limitations are described in [docs/WELLBEING_MODEL.md](docs/WELLBEING_MODEL.md).

> **Safety:** This is a prototype for wellbeing support. The dataset is synthetic and the recommendations are not clinically validated. It does not diagnose anything and is not a substitute for the Crew Medical Officer, flight surgeon or psychological support team. Validate the approach, human factors, privacy and operational procedures before any real crew use.

## Quick start (local, SQLite)

```sh
python -m venv .venv && .venv/Scripts/activate        # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate --settings=config.demo_settings
python manage.py generate_wellbeing_data --settings=config.demo_settings   # writes data/wellbeing_synthetic.csv
python manage.py train_recommender --settings=config.demo_settings         # writes ml_models/scene_recommender.joblib + model_card.json
python manage.py createsuperuser --settings=config.demo_settings
python manage.py runserver 8001 --settings=config.demo_settings
```

Sign in at `http://127.0.0.1:8001/accounts/login/`.

## What's in the app

- **Wellbeing (all signed-in users):** the check-in → recommendation → VR session → re-check flow, a mood chart, session history and per-world results. Each person sees only their own data.
- **VR sessions:** each theme world plays as an interactive 3D scene with its own soothing soundscape. The speaker button turns the sound on or off and the slider sets the volume (remembered on that device). Soundscapes are original, generated by `tools/make_ambience.py`.
- **Model (staff):** evaluation results, plus buttons to generate the synthetic dataset, upload a training CSV and retrain the model without the terminal.
- **Crew (staff):** a directory of astronauts and team members with portraits, roles and mission details.
- **Your profile:** click the avatar to edit your display name, title, biography and photo.
- **Meet the developers (staff, footer):** five developer profile slots.
- **Appearance (footer):** *Deep space* (dark) or *Daylight* (light). The choice is saved in the browser and kept in sync across tabs.
- **Installable PWA:** when there is no connection, the app shows an offline page. Check-ins and recommendations need the server, so nothing is stored offline.

## Crew profiles

Profiles include a portrait, call sign, role, agency, nationality, mission, mission start, date of birth, email, biography and crew status. Staff can view and edit all profiles.

Portrait uploads accept JPEG, PNG and WebP up to 5 MB and 20 megapixels. The app resizes portraits to 800 pixels, removes image metadata, and serves them through an authenticated endpoint with caching disabled. Back up the private `media/` directory with the database, and don't expose it through a public web server alias.

## Your profile

Display name, title, biography and photo are all optional; the avatar shows initials until you add a photo. Users can update only their own profile.

Choose a file, or select **Take a photo** to use the camera. Camera capture needs HTTPS (or localhost), browser support and permission; file upload still works if you decline. A captured photo stays unsaved until you select **Save my profile**. Account photos use the same checks as crew portraits and are served only to their owner.

## Run with PostgreSQL

Use Python 3.12 or newer and have PostgreSQL running. Create a database and role, then copy `.env.example` to a local `.env` and set the values. Do not commit `.env`.

```sh
pip install -r requirements.txt
cp .env.example .env          # set DJANGO_SECRET_KEY and DATABASE_URL
python manage.py migrate
python manage.py generate_wellbeing_data
python manage.py train_recommender
python manage.py createsuperuser
python manage.py runserver 8001
```

## Namecheap VPS deployment (`astrodoctor.space`)

These are Ubuntu-style commands; adapt package and service paths to your VPS image.

1. In Namecheap **Advanced DNS**, point the `@` and `www` A records at the VPS public IPv4 address. Allow inbound TCP ports 80 and 443 in the VPS firewall.
2. Install PostgreSQL, Nginx, Python and Certbot. Create a database and a dedicated local-only role:

   ```sql
   CREATE ROLE astrodoctor LOGIN PASSWORD 'use-a-unique-long-password';
   CREATE DATABASE astrodoctor OWNER astrodoctor;
   ```

3. Put the application on the VPS, create a Python virtual environment, install `requirements.txt` and `gunicorn`, and create a private `.env` beside `manage.py`. Set `DATABASE_URL` to the local PostgreSQL database, set a randomly generated `DJANGO_SECRET_KEY`, and set the allowed hosts and trusted HTTPS origins as shown in `.env.example`. Keep PostgreSQL bound to localhost unless you have a separately secured remote database.
4. Initialise the database, static files and model, then create the first staff account:

   ```sh
   python manage.py migrate
   python manage.py collectstatic --noinput
   python manage.py generate_wellbeing_data
   python manage.py train_recommender
   python manage.py createsuperuser
   ```

5. Run Gunicorn on `127.0.0.1:8000` as a supervised service (for example, systemd) so it restarts after reboot. Don't expose that port directly to the internet.

   ```sh
   gunicorn --workers 3 --bind 127.0.0.1:8000 config.wsgi:application
   ```

   Model training started from the **Model** page runs in a background thread inside the web process, so restarting Gunicorn interrupts any run in progress.

6. Configure Nginx to proxy requests to `127.0.0.1:8000`, forwarding the original `Host` and `X-Forwarded-Proto` headers. Use Certbot to issue TLS certificates for `astrodoctor.space` and `www.astrodoctor.space`, and redirect HTTP to HTTPS. The production settings require HTTPS for login and session cookies.
7. Before inviting users, verify sign-in, a full check-in → session → re-check cycle, model retraining, PWA install, and a database backup and restore. Keep regular encrypted PostgreSQL backups with restricted access: mood and wellbeing data is sensitive.

The PWA caches only its offline page and static assets, never wellbeing records.
